# Agent Spec

## Overview
A single-agent weather assistant built with the Python Agent Development Kit (ADK) and deployed to Google Cloud Agent Platform (Agent Runtime). Users can ask for current weather conditions and a multi-day forecast by providing either a city name (e.g., "Seattle, WA", "Tokyo") or a postal/zip code (e.g., "10001", "90210"). The agent resolves the location to coordinates and fetches live weather data using the free Open-Meteo APIs.

## Language
`python`

## Assumptions
- **Weather & Geocoding API**: Uses the public, no-auth [Open-Meteo Geocoding API](https://geocoding-api.open-meteo.com/v1/search) and [Open-Meteo Forecast API](https://api.open-meteo.com/v1/forecast) (with `zippopotam.us` fallback for numeric US/postal code resolution if needed so 5-digit zip codes resolve accurately).
- **Units**: Returns both Fahrenheit (°F) and Celsius (°C), plus wind speed in mph and km/h, so responses are immediately clear regardless of user locale.
- **Deployment Target & Region**: Prototype-first scaffold (`--prototype`), enhanced and deployed directly to GCP Agent Runtime (`--deployment-target agent_runtime`) in `us-central1` using the active `gcloud` project configuration, without CI/CD pipelines.
- **Session State**: Managed automatically by Agent Runtime (stateless tool calls; no cross-session memory bank required).

## Example Use Cases
1. **Weather by City Name**
   - **Input**: "What's the weather like in Austin, TX?"
   - **Expected Output**: Calls the weather lookup tool for "Austin, TX" and reports current temperature (°F/°C), weather condition description, humidity, wind speed, and a 3-day high/low summary.
2. **Weather by Zip Code**
   - **Input**: "Give me the forecast for zip code 10001."
   - **Expected Output**: Resolves zip code `10001` (New York, NY), fetches the Open-Meteo forecast, and returns current conditions plus the upcoming multi-day forecast.
3. **Unknown or Invalid Location**
   - **Input**: "What is the weather in ZzzNotARealPlace99999?"
   - **Expected Output**: Tool returns a structured location-not-found message; the agent politely informs the user that the location could not be found and asks for a valid city name or zip code instead of fabricating weather data.

## Tools Required
- **`get_weather(location: str) -> dict`**:
  - **Purpose**: Resolves a city name or zip/postal code to latitude/longitude (and canonical place name) and fetches current weather conditions (temperature, feels-like, humidity, wind speed, weather code description) plus a 3-day daily forecast (high/low temperatures, precipitation probability, condition) from Open-Meteo.
  - **API Details**:
    - Geocoding: `GET https://geocoding-api.open-meteo.com/v1/search?name={location}&count=1&language=en&format=json` (with fallback to `GET https://api.zippopotam.us/us/{zip}` when a 5-digit US zip code is not directly resolved by Open-Meteo's search endpoint).
    - Weather: `GET https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lon}&current=temperature_2m,relative_humidity_2m,apparent_temperature,weather_code,wind_speed_10m&daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_probability_max&temperature_unit=fahrenheit&wind_speed_unit=mph&timezone=auto&forecast_days=3`
  - **Authentication**: None required (free public APIs).

## Constraints & Safety Rules
1. **No Hallucinated Weather Data**: The agent must never guess or fabricate temperatures, forecasts, or weather conditions. Every weather report must come directly from the `get_weather` tool output.
2. **Scope Boundary**: The agent only answers weather and location-forecast questions. If asked unrelated questions (e.g., medical, financial, coding, or general trivia), it politely declines and states that it only provides weather information.
3. **Graceful Error Handling**: Network timeouts or unresolvable locations must return a clear structured error dictionary from `get_weather` (never raise unhandled exceptions that crash the turn).

## Success Criteria
1. **Tool Trajectory**: `tool_trajectory_avg_score` reaches `1.0` across eval cases covering city lookup, zip code lookup, and out-of-scope / invalid-location prompts.
2. **Response Quality**: `response_match_score` / rubric evaluation passes (`>= 0.8`) confirming responses include resolved location name, current temperature, weather conditions, and forecast summary when a valid city or zip code is requested.
3. **Deployment**: Agent deploys cleanly to GCP Agent Runtime via `agents-cli deploy` and responds to a live test query.
